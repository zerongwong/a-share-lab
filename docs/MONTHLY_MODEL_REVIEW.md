# 月度模型复盘与迭代边界

月度复盘只读取不可变推荐档案和已经完成的到期结果。它不重跑旧预测、不改旧权重，也不会
因为看到后续价格而改变当时的候选、介入条件或模型版本。

批次结果和逐股结果属于后续可重试的观察记录，因此复盘会分别检查每一行的 `evaluated_at`、
`updated_at` 和 `data_cutoff`。任何缺少可审计生成时间、或晚于复盘 `as_of` 才生成/更新的行，
都不能进入当时的覆盖率、未触发或原因统计。这样即使一次重试只更新了逐股行、尚未更新批次
行，也不会把未来才知道的诊断证据带回历史月报。

## 什么时候运行

复盘对象是**上一个完整自然月内到期**的组合。服务不依赖“每月1日”这个容易遇到周末或
休市日的固定日历任务：调度器在收盘同步首次确认本月已有一个新交易日后调用
`monthly_review_due`，它才会返回上月；本地独立完成状态会抑制同月后续重复运行。若月初连续
休市，复盘自然推迟到首个数据同步成功的交易日。

完成状态只保存月份键和状态版本，不保存凭据、原始行情或推荐正文。调用方应在自己定义的
成功边界后写入完成状态；例如，若月报需要通知，可以在至少一个通知服务商受理后再标记，
这样发送失败时仍可安全重试。

当前收盘调度采用**仅本地成功边界**：完整复盘先原子写入
`scheduler/monthly-model-reviews/YYYY-MM.json`，目录权限为 `0700`、文件权限为 `0600`，
写入成功后才记录该月已完成。调度日志只保留月份、状态和聚合数量；不会包含组合明细，
也不会把月报提交给 Server酱或 Bark。任一步失败都不改变收盘数据已追平的结论，并在下次
15:30 / 18:30 / 20:00 调度时重试。

## 统计总体与期限

以下三张榜永久分开：

1. 正式行动：原始档案、通知曾被服务商受理、当时具备行动资格；
2. 原始观察：当时自动冻结但不具备正式行动资格；
3. 重建观察：日后按指定历史截止日重新运行当前模型得到的观察档案。

每张榜再分别统计 1周、2周、1个月、3个月、6个月、1年。不同期限可能重叠持有同一股票，
因此不能把六期限或三张榜合并成独立样本，也不能把相同股票重复出现当成置信度倍增。

每个期限列出：

- 本月已成熟组合数及可核验收益数；
- 组合内部按发布时原权重计算后的平均表现；正式行动同时保留账户层和股票仓层口径，观察榜
  只使用股票仓层口径；
- 负收益组合清单；
- 同区间、同日期且来源与方法版本完整的基准证据可用时，列出股票仓相对基准表现和弱于基准
  清单；否则明确为 `unavailable`，不临时抓取不一致的指数数据代替；
- 成员收益数据覆盖、公司行动证据覆盖、公司行动明确无异常覆盖及未触发数量。

## 原因框架不是因果结论

对负收益或弱于基准的组合，程序只生成可核查线索：候选数量、当时周期标签、归档的主结构、
风险/收益下界状态、未触发数量、数据覆盖和公司行动覆盖。当前绩效档案没有保存点时点行业
归属，因此行业集中度必须显示为不可用，不能拿今天的行业分类回填旧组合。

这些线索用于形成后续问题，不证明某一个门槛“导致”了亏损。尤其不得：

- 用到期后的价格重写旧预测；
- 从单月样本中挑出最漂亮的参数并直接上线；
- 把没有触发的现金仓事后分配给上涨股票；
- 将未复权原始价格变化当成含分红总回报；
- 混合正式行动、原始观察和历史重建得出一个总胜率。

当前自动流程**尚未接入生产级同区间市场基准加载器**。因此默认月报会明确写“基准不可用”，
不会把缺失基准解释成跑赢、跑输或持平。只有独立调用方提供批次完全匹配的基准编号、计划日、
到期日、数据截止日、计算日、未复权口径、来源和方法版本时，才允许生成股票仓相对基准结果；
基准计算日还必须不晚于月报 `as_of`。正式行动榜展示的主收益是总资金模拟收益，而相对基准
始终使用股票仓收益，消息会明确区分这两个口径。

## 模型升级纪律

单一总体、单一期限至少有 12 个收益可核验的成熟组合之前，只报告“证据不足”，不对模型优劣下方向性
结论。达到最低描述样本后，程序仍只可以输出带版本号的实验建议，例如相对强度消融或介入
确认规则消融。实验必须使用新的点时点数据、purged walk-forward、费用与滑点、最差折和
多重比较调整后的区间；旧版本保留为对照。

任何建议默认状态都是 `proposal_only_user_confirmation_required`。只有用户讨论并确认，且新
样本外证据通过验收后，才能另行修改模型版本；月度复盘本身没有自动调参、写策略或下单能力。

最低样本门槛按**可核验组合收益数**计算，不按仅仅“已经到期但数据不可核验”的批次数计算。
如果档案查询达到扫描上限，程序无法证明总体完整：此时仍可列出已看到的事实，但必须标记
`archive_scan_truncated`，禁止方向性结论和实验建议。生产化前应改用按到期月份分页查询，消除
扫描上限，而不是提高上限后假装样本完整。

## 手动预览

```bash
python -m ashare_lab.cli.monthly_model_review \
  --month 2026-08 --as-of 2026-09-01 --format message
```

该命令只在本机生成预览，不发送微信/Bark，不连接券商，也不安装定时任务。省略 `--month`
时默认复盘当前日期之前的完整自然月。把月报正文自动发送到 Server酱/Bark 属于单独的外发
授权边界；未明确启用前，服务只生成本地结果和通知预览。
