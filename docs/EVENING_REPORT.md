# 21:00 次日研究报告

本项目用两个彼此独立的本机任务完成四个阶段：

1. 15:30 首次同步当天已经收盘的沪深 A 股与核心指数；数据确认追平最新完整交易日后，独立
   检查并结算已经到期的推荐档案，同时在本机复核用户明确登记且仍有效的持仓；
2. 18:30 再做一次幂等质量复核；若 15:30 数据尚未通过，本次验证通过后再触发同一幂等结算
   与持仓复核；持仓明细和保护线只写本地账本，调度日志只记录动作数量；
3. 20:00 做晚报前最后一次幂等预检；若前两次遇到短暂上游故障，本次仍从原有已验证截止日
   继续补齐，且继续受同一共享锁、连续交易日链和质量门保护；
4. 周日至周四 21:00 检查是否存在新的、完整且已验证交易日；只有交易日链确认存在可用的
   下一交易日计划且未处理过同版本报告时，才冻结新档案，并分别向用户已配置的 Server酱与
   Bark 提交新计划摘要。

周五、周六不发送计划报告。周日只是允许检查的日历日，并不被程序先验认定为交易日前夜；
节假日、调休和休市安排由已验证交易日链、新数据截止日及去重状态共同决定。

选择 21:00 作为主报告时间，是为了让收盘数据有充分时间完成覆盖率、单位、交易日连续性
和核心指数共同截止检查，同时给使用者在睡前留出阅读时间。当前版本不在次日早晨重复发送
同一份报告；以后只有在接入合规的隔夜公告与停复牌数据后，才适合增加“08:50 仅异常提醒”。

## 报告内容

每份报告必须带数据共同截止日，并明确它适用于“共同截止日后的下一交易日”。通知是给人
阅读的精简行动摘要，Server酱与 Bark 正文都不得超过 2400 个 UTF-8 字节，依次只展示：

- 市场价格周期、进攻/防守姿态、股票敞口上限与最低现金；
- 对该具体通道已明确授权时，才显示用户已登记持仓的当日修枝摘要；
- 1 周、2 周、1 个月、3 个月、6 个月、1 年六个研究周期；
- 每个周期压成一行，只保留股票名称/代码、股票仓内 10% 整数档、价格条件；
  没有合格结果时直接写“无合格”或“数据不足”；
- 一行研究与不自动下单说明。

六期限候选重合、Jaccard 值、差异归因和独立过门证据仍保留在不可变研究档案中，
用于方法审计；它们不再出现在 Server酱或 Bark 每日消息中。精简通知不得删除或
改写底层审计字段。

### 已登记持仓图表

当本机登记的是 4 只、1 个月周期持仓，并且至少一个目标通道已获得该通道的持仓摘要授权
时，21:00 任务可以生成一张手机优先的纵向复合图：每只股票按“日线 → 完整周线”连续排列，共 8 个
面板。图表采用低饱和粉、紫、蓝配色组织信息，但蜡烛仍遵循 A 股红涨绿跌。图中只包含：

- 模型原观察条件；历史重建时必须注明“非行动、非买入许可”；
- 对应周期均线与量能；
- 已确认的结构基准、保护参考或当前有效保护线。

所有辅助线只从其当时可知日期开始绘制，不向更早的历史回画；当周尚未完成的周线会被
排除。图表不展示持仓成本、股数、金额、账户权重，也不把一条观察线表述成可以立即买入。

图表生成与外发是两件事。逐通道持仓摘要授权是本机生成和归档该持仓图的前置条件；未获准
的通道不会触发其持仓图外发。生成的 PNG 默认只进入本机私有目录，目录权限为 `0700`、
文件权限为 `0600`，并按 30 天保留期清理。文字晚报仍可按原有配置发送；图表生成、归档或
图片传递失败时，系统退回精简文字，不因此阻断另一通道。

Server酱和 Bark 都只能消费一个可从手机访问的 **HTTPS 图片 URL**，不能读取 Mac 本地路径。
项目支持把获准的持仓图私密上传到 Cloudflare R2，再把短期签名 URL 仅附在 Server酱
消息中；Bark 始终不带图。开箱状态没有 R2 坐标、密钥或图片通道授权，因此仍只会保留
本机私有图。项目不会把持仓图上传到公开图床、GitHub 或 GitHub Pages；仅配置文字通道
密钥也不会自动启用图片上传。

通知设置页可以预先保存 Cloudflare R2 的 Account ID、私有存储桶名称和签名地址
有效期；这些非密钥项只进入权限为 `0600` 的本机配置文件。R2 Access Key ID 与
Secret Access Key 则分别保存到 macOS 钥匙串，不写入该文件。对象目录固定为
`holding-charts`，签名地址默认有效 3600 秒。存储桶必须保持私有，并在 R2 端配置
1 日自动删除规则。生产发布还要求在本机明确确认“私有桶”和“1 日删除”两项，并在持仓
版本中另行授权 `serverchan + cloudflare_r2`；任一条件缺失都会退回纯文字。

持仓文字摘要授权不等于持仓图授权。即使某通道已允许文字摘要，图片仍默认禁止外发。
当前图片权限只支持“仅 Server酱”；Server酱、下游微信与 Cloudflare R2 会接触图像或短期
签名 URL，并可能在地址到期前拉取或缓存图片。上传前、上传后和每次服务商提交前都会复核
同一持仓版本、数据截止日和授权；授权变化或 Server酱未受理图片时会尽力立即撤销对象。

晚报把“行情证据截止日”和“持仓/授权知识时间”分开处理：例如 9 月 2 日晚间可用 9 月 1 日
已核验完整收盘数据，同时采用 9 月 2 日用户刚确认的当前持仓与图片授权。实时发送会冻结并
复核该精确持仓版本；普通历史回放仍只读取截止日当时已经生效的版本，不会取得未来授权。

持仓修枝由 15:30 / 18:30 / 20:00 本机任务照常复核；21:00 晚报只有在至少一个通道获准时才读取
本机复核结果并生成外发摘要。外发采用严格、默认关闭的逐通道授权。当前持仓快照只认
`holding_summary_delivery_channels` 明确允许列表，且只接受 `serverchan`、`bark`；空列表
表示两个通道都不外发。旧的 `external_delivery_consent` 布尔值不构成任何授权。
Server酱与 Bark 分别渲染，未授权通道的正文不会出现持仓标题、提示或失败信息；一个通道
获准不会连带授权另一个通道。复核失败时，也只有已授权通道显示“持仓复核不可用”。

获准外发的持仓摘要仍是最小披露：只含股票代码/名称、持有周期、HOLD/收紧/减仓/退出/复核、
有效保护线和简短理由。成本、总金额、股票仓内权重及账户权重永不进入第三方通知。没有一份
用户明确登记且仍有效的持仓快照时，即使底层调用异常也不外发持仓信息。

授权只能随一次明确的整组持仓替换一起保存。本机页面需分别勾选 Server酱/Bark；命令行
则使用 `--allow-holding-summary-serverchan`、`--allow-holding-summary-bark`。两项均不选
就是默认关闭；清空持仓也会清空允许列表。授权不连接券商，也不启用自动下单。

“规则一致度”不是牛熊概率；价格周期标签也不是对牛熊起止时间的预测。风险合格计划仍不是
券商持仓或自动订单。观察配比不换算为总资金仓位，观察线被触及也不等于可以买入。

## 与到期复盘的边界

21:00 晚报只处理**下一交易日的新计划**，不负责结算旧计划。到期复盘由 15:30 / 18:30 / 20:00
收盘同步在已验证日线追平后触发，并使用独立的通知事件和去重键；所以到期通知可能早于
21:00 单独到达，也不会被拼接成晚报发送成功的前置条件。

到期结果严格分成三张榜：正式行动榜、原始观察榜和重建观察榜。三者不能合并计算收益或
胜率；旧消息也不会在安装或升级后自动回填成正式行动档案。期限到期日、未复权价格收益、
原权重不重标及公司行为失败边界见
[六周期推荐的滚动到期复盘](PERFORMANCE_TRACKING.md)。

## 数据与安全边界

- CSMAR 历史库始终只读；当前零预算三源当日增量保存在本机、按来源隔离的
  `zero_budget_eod` overlay 中，旧 Infoway 链不混入；
- 一个周期失败只影响该周期，不能沿用前一日或另一周期的结果；
- 没有新的已验证交易日时不重复提交；同一共同截止日与方法版本只处理一次；
- 到期复盘与新计划彼此独立：收盘同步失败不冒充已结算，21:00 新计划受理也不冒充到期
  复盘已送达；
- Server酱和 Bark 彼此独立；两者都接收保留全部周期、候选、配比和价格条件的
  2400 字节内精简摘要；系统尝试每个已配置通道，至少一个服务商明确受理后才登记去重
  状态，一个通道失败不会阻止另一个通道尝试；
- 可选持仓图默认只在本机私有归档；没有另行授权的私有短期签名 HTTPS 图片服务时，
  Server酱/Bark 只发送精简文字，不使用公开图床或 GitHub 代传；
- “服务商已受理”只证明第三方 API 接收请求，不等于微信或 iPhone 终端已经送达；
- Server酱 SendKey 只从 macOS 钥匙串读取，不进入 plist、命令行、日志或 GitHub；
- 微信只接收衍生研究摘要，不接收原始行情、CSMAR 数据、API 响应或密钥；
- 程序不连接券商、不读取真实账户仓位、不自动下单。

GitHub 只保存代码、方法文档和合成测试。任何授权数据库、本地报告、Parquet、DuckDB、
SQLite 和凭据均由 `.gitignore` 排除。

## 本机运行

手动生成并向已配置服务商提交一次报告：

```bash
.venv/bin/python -m ashare_lab.cli.evening_report
```

安装独立的周日至周四 21:00 macOS 任务：

```bash
./scripts/install_evening_report_launchagent.sh
```

任务使用 `com.zerong.asharelab.evening-report` 标签，不会重启网页或每日数据同步任务。
电脑关机时无法发送；下次登录或唤醒后，`RunAtLoad` 会唤起任务。命令行发送门会先阻止
周五、周六发送，再由交易日链、新截止日和去重规则决定其余日历日是否发送。

如果程序记录 Server酱已受理但微信没有出现消息，请登录 Server酱查看该次推送日志，并检查
微信通道的关注或绑定状态；Bark 是独立通道，可作为微信未送达时的兜底。两边都未收到时，
先在通知设置页分别测试两个服务商，再查看本机晚报日志中的脱敏受理状态。
