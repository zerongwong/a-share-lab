# 09:00 当日盘前研究报告

> 当前生产盘前报告为 `continuous-signal-v4`：一组按信号持续跟踪、无强制到期的组合，
> 具体约束见[连续组合合同](CONTINUOUS_STRATEGY.md)。本文标为历史兼容的固定期限档案与
> 到期复盘，不构成当前生产的六期限推荐，也不改变已登记持仓。

本项目将数据同步、主报告、独立截止检查和持仓日报分为独立任务：

1. 15:30 首次同步当天已经收盘的沪深 A 股与核心指数；数据确认追平最新完整交易日后，只在
   本机复核用户明确登记且仍有效的连续策略持仓；旧固定期限档案不再结算或推送；
2. 16:30、18:30、20:20 依次做幂等质量复核；若较早一次遇到短暂上游故障，后续运行仍从
   原有已验证截止日继续补齐；验证通过后才触发同一幂等持仓复核。持仓明细和保护线
   只写本地账本，调度日志只记录动作数量；
3. 次日 06:30、07:30、08:00 再做幂等补齐；夜间暂不可用的免费数据源因此有更长恢复时间；
4. 08:18–09:00 不再启动新的收盘同步；晨间活跃同步由监管进程在08:18前收尾释放共享锁，
   不删除活锁、不把半成品当成已验证数据；
5. 周一至周五 08:20 首次尝试，08:30、08:40、08:50 有限重试，目标09:00前收到；仅在 08:20–08:58（不含08:58）窗口，
   且“今天”经交易日历确认是共同截止日后的下一交易日时提交计划。默认自动任务仅向 Server酱发送。
   当前生产路径只提交精简文字和持仓预警；图片外发已关闭，不因缺图产生补图重试。

常规任务若开始构建后到达 08:58，会记录明确的
`morning_window_ended_before_submission` 失败，不再记为成功跳过，也不写受理状态。
数据截止检查会在全市场构建前执行，正式提交前再复核一次。自动入口为每次计算设置 8 分钟上限：
超时后仅终止该次任务的独立子进程组，释放数据锁，让下一次有限重试有机会执行。
盘前任务采用普通进程优先级，不施加后台CPU/磁盘节流；接近08:58启动的任务还会按剩余时间缩短预算。
脱敏日志依次记录交易日历、全市场计算、归档、排版和推送阶段及耗时，便于区分卡点。

首次受理时登记提醒去重，该状态独立于正式计划，后续成功计划仍可正常提交。
网络响应丢失或超时仍记为未知，不伪造受理状态；后一个截止时点可有限重试，因此不能保证第三方严格只送达一次。

提醒不含持仓、图片、密钥或原始报错，也不把未知的持仓状态认定为继续持有或卖出。

### 两份日报的当前边界（2026-09-22）

- 空仓：盘前继续全市场筛选、周线突破与财务/公告双重确认、组合风险比较；合格数量可为0–5只。
- 已登记持仓：盘前直接复核这些股票，按风险优先展示继续持有/收紧保护/减退/待核验；
  不等待全市场重新筛选，不每天用新排行榜替换原仓。买卖只能由用户确认后更新登记。
- 收盘：仅有有效登记持仓时推送，按当日15点后双源一致快照估算**相对已确认成本的累计浮盈亏**，
  列逐股百分比、盈亏金额及股票持仓合计。它不是当日涨跌幅、全账户净收益或已清仓股票的已实现收益。
  未录入的分红、费用与现金不臆造；缺成本、股数、报价或公司行为核验，明确待补齐，不把缺失当0。
- 收盘金额外发要求独立的Server酱授权，不由原先“不含金额的持仓摘要授权”推导。
  仅外发已授权盈亏字段，不另发本金、股数、总市值或账户总资产。
- 盘中现有约每分钟检查保留，只有风险触发或监控失联才提醒，不是毫秒级行情、成交指令或必达承诺。

新建仓登记JSON增加可选`quantity`（实际正整数股数）；金额日报不能用推荐权重猜股数。
不持仓时收盘任务保持静默；最后一次收盘尝试仍未核验完，可发送该份日报的缺项状态，不追加第三类通知。

### 盘前故障诊断

“盘前计划暂未完成”表示计算或提交未完成，不表示全市场没有合格股票。
先查 `~/Library/Logs/A股研究助手/evening-report.jsonl`：

- `evening_worker_deadline_exceeded`：该次计算超过8分钟，由监管进程终止；
- `in_progress` 的最后一个 `stage`：区分交易日历、全市场计算、归档、排版、服务商提交；
- `daily_data_lock_busy`：同步任务仍持有共享数据锁；
- `verified_market_data_stale_for_today`：数据仍未追平当天所需的上一完整交易日；
- `provider_accepted`：服务商已受理正式日报，仍不等于手机端已读或已送达。

排障时一并核对 `daily-sync.jsonl` 的共同截止日和实际运行任务的解释器、工作目录及优先级。
不要根据一次无候选结果推断推送故障，也不要根据故障提醒推断模型筛出了零只股票。
本机 LaunchAgent 的安装成功只证明本机定时配置已生效，不证明已部署到云端。

周六、周日不发送计划报告。工作日也不被程序先验认定为交易日；节假日、调休和休市安排由
已验证交易日链、新数据截止日及去重状态共同决定。

选择次日 09:00，是为了给免费收盘源完整的隔夜恢复时间，同时在 09:30 开盘前留下人工阅读和
决定时间。报告使用上一完整交易日的共同截止数据；同一计划受理后不重复发送。

## 报告内容

每份报告必须带数据共同截止日，并明确它适用于“共同截止日后的下一交易日”。通知是给人
阅读的精简行动摘要，通常压到 2400 个 UTF-8 字节以内。多只持仓风险事项与完整限价条件同时
出现时，Server酱可回退到最多 4096 字节的完整 Markdown，不因误套 APNs 限额而丢掉整条盘前报告；
4096 是本项目主摘要排版上限，不是服务商限额，不包含随后附加的缺图提示和签名图片地址。
Bark 的紧凑正文仍严格限制 2400 字节；其渲染失败不阻断 Server酱，且不因此放宽权限或
Bark 通道大小检查。依次展示：

- 市场价格周期、进攻/防守姿态、股票敞口上限与最低现金；
- 对该具体通道已明确授权时，才显示用户已登记持仓的当日修枝摘要；有风险事项时标题标注
  “次日优先处理”，已确认的退出/减仓用醒目标签，并排在其余持仓之前；
  单维度转弱仅提示“优先复核减仓”，不把预警升级为已确认执行；计划日未确认时标题改为“风险优先核验”；
- 公司行动证据缺失而阻断的破位/转弱，显示“疑似破位/转弱”和“优先核验·非卖出确认”，
  不隐藏风险原因，也不把待核验事项升级为卖出许可；
- 只展示一组连续计划：保留结构完整的旧仓，出现退出信号时先处理待确认事项，再评估替补与现金；
- 组合可为 0–5 只：1–5只在相同风险预算下比较，0只表示暂留现金，不为凑数降低门槛；
  每行业最多一只，新建仓单股总账户权重不超过 20%，约 15% 只是中枢；
- 合格新买计划保留股票名称/代码、建议新买比例与完整价格条件。初建是股票仓内 10% 档，
  后续单只补位枚举总账户 10%/20% 档；初建和补位均须通过单股 20% 总账户硬上限，旧仓权重随市值漂移，不为凑整数而调仓；
  不合格或证据不足写“仅观察·暂不建仓”。卖出尚未确认、现金未核实时，不发正式补位买入许可；
- 一行研究与不自动下单说明。

旧版固定期限兼容：六期限候选重合、Jaccard 值、差异归因和独立过门证据保留在旧研究档案中，
不出现在当前每日消息，也不因通知改版而改写历史审计字段。

### 已登记持仓图表（历史兼容，生产已停用）

当前定时盘前报告按用户选择只发送文字，不生成、上传或发送持仓图片，也不需要 Cloudflare R2。
下述图表流程仅保留给历史档案、离线测试和未来明确重新授权的场景，不参与生产推送。

这条历史图表链只验证过 1–5 只有效持仓；即使未来重新授权，超过 5 只也须先扩展并重新验收。
当本机登记的是 1–5 只有效持仓，并且至少一个目标通道已获得该通道的持仓摘要授权
时，历史图表任务可以生成一张手机优先的纵向复合图：每只股票按“日线 → 完整周线”连续排列，
共 2N 个面板，四只仍为八图。明确卖出一只并更新登记后，不再因为少于四只而拒绝剩余持仓图；
零持仓不生成或外发持仓图。连续策略固定采用日线与完整周线，不受旧持有周期字段影响。
图表采用低饱和粉、紫、蓝配色组织信息，但蜡烛仍遵循
A 股红涨绿跌。图中只包含：

- 模型原观察条件；历史重建时必须注明“非行动、非买入许可”；
- 对应周期均线与量能；
- 已确认的结构基准、保护参考或当前有效保护线。

所有辅助线只从其当时可知日期开始绘制，不向更早的历史回画；当周尚未完成的周线会被
排除。图表不展示持仓成本、股数、金额、账户权重，也不把一条观察线表述成可以立即买入。

图表生成与外发是两件事。逐通道持仓摘要授权是本机生成和归档该持仓图的前置条件；未获准
的通道不会触发其持仓图外发。生成的 PNG 默认只进入本机私有目录，目录权限为 `0700`、
文件权限为 `0600`，并按 30 天保留期清理。文字报告仍可按原有配置发送；图表生成、归档或
图片传递失败时，系统保留文字发送结果并独立记录待补图，不把“文字受理”标成“图片受理”。
盘前窗口内的有限图片尝试会重签短期地址，仅补图、不重复连续计划全文。窗口结束仍失败
保留明确失败状态；次日不会无限重发过期计划，也不能承诺旧签名链接永久有效。

Server酱和 Bark 都只能消费一个可从手机访问的 **HTTPS 图片 URL**，不能读取 Mac 本地路径。
项目支持把获准的持仓图私密上传到 Cloudflare R2，再把短期签名 URL 仅附在 Server酱
消息中；Bark 始终不带图。开箱状态没有 R2 坐标、密钥或图片通道授权，因此仍只会保留
本机私有图。项目不会把持仓图上传到公开图床、GitHub 或 GitHub Pages；仅配置文字通道
密钥也不会自动启用图片上传。

通知设置页可以预先保存 Cloudflare R2 的 Account ID、私有存储桶名称和签名地址
有效期；这些非密钥项只进入权限为 `0600` 的本机配置文件。R2 Access Key ID 与
Secret Access Key 则分别保存到 macOS 钥匙串，不写入该文件。对象目录固定为
`holding-charts`，签名地址默认有效 3600 秒。存储桶必须保持私有，并在 R2 端配置
1 日自动删除规则。生产发布还要求在本机明确确认“私有桶”和“1 日删除”两项，并在持仓
版本中另行授权 `serverchan + cloudflare_r2`；任一条件缺失都会退回纯文字。

持仓文字摘要授权不等于持仓图授权。即使某通道已允许文字摘要，图片仍默认禁止外发。
当前图片权限只支持“仅 Server酱”；Server酱、下游微信与 Cloudflare R2 会接触图像或短期
签名 URL，并可能在地址到期前拉取或缓存图片。上传前、上传后和每次服务商提交前都会复核
同一持仓版本、数据截止日和授权；授权变化或 Server酱未受理图片时会尽力立即撤销对象。

盘前报告把“行情证据截止日”和“持仓/授权知识时间”分开处理：例如 9 月 2 日早晨可用 9 月 1 日
已核验完整收盘数据，同时采用发送前已经确认的当前持仓与图片授权。实时发送会冻结并
复核该精确持仓版本；普通历史回放仍只读取截止日当时已经生效的版本，不会取得未来授权。

持仓修枝由收盘后及次日早晨的同步任务照常复核；09:00 盘前报告只有在至少一个通道获准时才读取
本机复核结果并生成外发摘要。外发采用严格、默认关闭的逐通道授权。当前持仓快照只认
`holding_summary_delivery_channels` 明确允许列表，且只接受 `serverchan`、`bark`；空列表
表示两个通道都不外发。旧的 `external_delivery_consent` 布尔值不构成任何授权。
Server酱与 Bark 分别渲染，未授权通道的正文不会出现持仓标题、提示或失败信息；一个通道
获准不会连带授权另一个通道。复核失败时，也只有已授权通道显示“持仓复核不可用”。

获准外发的持仓摘要仍是最小披露：只含股票代码/名称、连续持仓标识、HOLD/收紧/减仓/退出/复核、
有效保护线和简短理由；公司行为证据不足时，必须改为“暂持有·待核验”和“参考线”，
不宣称已建立可持续上移的保护线。成本、总金额、股票仓内权重及账户权重永不进入第三方通知。没有一份
用户明确登记且仍有效的持仓快照时，即使底层调用异常也不外发持仓信息。

授权只能随一次明确的整组持仓替换一起保存。本机页面需分别勾选 Server酱/Bark；命令行
则使用 `--allow-holding-summary-serverchan`、`--allow-holding-summary-bark`。两项均不选
就是默认关闭；清空持仓也会清空允许列表。授权不连接券商，也不启用自动下单。

“规则一致度”不是牛熊概率；价格周期标签也不是对牛熊起止时间的预测。风险合格计划仍不是
券商持仓或自动订单。观察配比不换算为总资金仓位，观察线被触及也不等于可以买入。

## 旧版到期复盘（已退役，生产只读）

当前连续组合不按一周、一个月等期限强制卖出。它的独立净值记录需要明确的实际账户快照、
可核验价格和无外部资金流声明；缺输入不伪造收益。旧固定期限到期结算、Server酱到期通知和
旧月度复盘已于 2026-09-18 从生产自动任务中退役，待到期批次不会继续自动追踪。冻结的历史
推荐原样保留、不删除、不改写，也不会成为当前荐股或持仓；只有明确执行离线审计时，才允许
追加或刷新派生结算记录。

v2 迁移本身不推断成交，也不自动把旧组合改成空仓。开源使用者须在明确确认已空仓后写入 `cleared` revision；
本机这次切换已用显式空仓 revision 将旧组合移出活跃盘前跟踪，旧持仓、保护线、通知、决策和绩效记录仍作为不可改写审计档案保留。
在使用者下一次明确确认真实建仓之前，持仓段保持空状态，不从荐股或通知推测成交。
该次明确确认会建立新 revision、新 `position_key` 和隔离的 `continuous-signal-v3` 追踪身份；
真实绩效链仍须从完整、明确确认的账户估值快照建立，不能从推荐或通知推测成交。

09:00 盘前报告只处理**当日的一组连续计划**。收盘同步不再触发旧计划到期复盘；旧的结算
命令只能用于明确的离线历史审计，默认不外发，不能写成当前荐股。

到期结果严格分成三张榜：正式行动榜、原始观察榜和重建观察榜。三者不能合并计算收益或
胜率；旧消息也不会在安装或升级后自动回填成正式行动档案。期限到期日、未复权价格收益、
原权重不重标及公司行为失败边界见
[六周期推荐的滚动到期复盘](PERFORMANCE_TRACKING.md)。

- CSMAR 历史库始终只读；当前零预算三源当日增量保存在本机、按来源隔离的
  `zero_budget_eod` overlay 中，旧 Infoway 链不混入；
- 当前单组计划的证据失败时不提供新买许可，不能沿用前一日或旧固定期限结果冒充当日计划；
- 同期文字已受理就不重复全文；该期图片尚未受理仍只能在当次盘前窗口内有限补发；
- 旧到期复盘已退出生产自动化；09:00 新计划受理不能改写或重新激活旧档案；
- 自动任务默认仅 Server酱，不因钥匙串还留有 Bark 密钥就新增外发通道。
  底层显式通道选项保留兼容；文字遵守上文各通道预算，并保留必要行动资格和完整价格条件，
  服务商明确受理后才登记相应去重状态；
- 可选持仓图默认只在本机私有归档；没有另行授权的私有短期签名 HTTPS 图片服务时，
  Server酱/Bark 只发送精简文字，不使用公开图床或 GitHub 代传；
- “服务商已受理”只证明第三方 API 接收请求，不等于微信或 iPhone 终端已经送达；
- Server酱 SendKey 只从 macOS 钥匙串读取，不进入 plist、命令行、日志或 GitHub；
- Server酱连接建立失败时，可尝试其官方域名当前解析出的其他地址；保留原 Host、TLS SNI 和
  证书校验，不使用固定 IP、不跟随重定向。读取或写入失败、服务商 HTTP 响应不触发立即重发，
  避免在服务商可能已经受理时复制同一请求；
- 微信只接收衍生研究摘要，不接收原始行情、CSMAR 数据、API 响应或密钥；
- 程序不连接券商、不读取真实账户仓位、不自动下单。

GitHub 只保存代码、方法文档和合成测试。任何授权数据库、本地报告、Parquet、DuckDB、
SQLite 和凭据均由 `.gitignore` 排除。

## 本机运行

按常规 08:20–08:58（不含08:58）窗口生成并向已配置服务商提交一次报告：

```bash
.venv/bin/python -m ashare_lab.cli.evening_report
```

需要人工补发时，使用明确的即时发送选项（当日盘前自动窗口内）：

```bash
.venv/bin/python -m ashare_lab.cli.evening_report --send-now
```

该选项采用真实本地时间，只发送适用于今天且经交易日历核实的计划；仍检查
共同截止日、数据新鲜度、持仓授权和同计划去重。不能用旧数据补发过期买入建议，不能借此
改写历史决策日期，非交易日仍不发送计划。函数和生产入口均默认纯文字；旧图片授权或
待补图状态不会重新启用图片。此选项不改变已有定时配置；显式人工运行仍是前台同步
计算，不套用自动任务的 8 分钟监管；不得绕过所用入口的提交时间门。

一次安装三个独立的 macOS 任务（主报告08:20起四次尝试、截止检查08:58/08:59、持仓日报15:35起三次尝试）：

```bash
./scripts/install_evening_report_launchagent.sh
```

三个标签分别是 `com.zerong.asharelab.evening-report`、`com.zerong.asharelab.preopen-deadline`、
`com.zerong.asharelab.holding-pnl`，不会重启网页或每日数据同步任务。安装前核验全部模板和模块，
任一登记失败会恢复原plist、加载和禁用状态；卸载脚本也同时移除这三个任务，保留研究数据和凭据。
新任务模板用 `caffeinate -i` 仅在本次报告任务运行期间阻止闲置休眠，结束后自动解除；
它不修改全局电源设置，不能在电脑关机或已经睡眠时保证 09:00 准时启动。
电脑关机时无法发送；下次登录或唤醒后，`RunAtLoad` 会唤起任务。命令行发送门会先阻止
周末及发送窗口外的执行，再由当天是否交易日和去重规则决定是否发送。

如果程序记录 Server酱已受理但微信没有出现消息，请登录 Server酱查看该次推送日志，并检查
微信通道的关注或绑定状态，再查看本机盘前报告日志中的脱敏文字和图片受理状态。
本项目当前按用户选择仅使用 Server酱，不自动改投其他服务商。
