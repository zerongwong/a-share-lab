# 候选财务与重大风险核验

生产流程为“周线突破/健康回踩候选 → 财务与重大风险核验 → 可交易性与组合比较”。
2026-10-11 经用户确认，使用 `candidate-evidence-v2.0.0` 取消全量公告逐条人工审批的独立门；
不取消重大风险、最新财报、审计、可交易性或公司行动证据。通过不代表全面尽调或保证盈利。
下方命令是遇到复杂公告时的**人工/研究者正文审阅工具**，不是自动尽调工具；
分项证据仍单独归档，但准入使用一个 `fundamental_risk_gate`，任何单项通过都不代表最终允许买入。

## 自动初筛与人工审阅的界线

自动核验使用决策时已披露的最新适用结构化财务数据、官方清单，以及有身份、时间和哈希证据的指定正文。
非金融企业至少核对当期与去年同期盈利、盈利能力、资产负债和经营现金转换；
PE(TTM)、PB(MRQ) 仅是带价格截止日的背景，不代替业绩或风险检查。
最新完整财报、最近年度审计与可能改变财务结论的重大事项需要正文证据。
普通制度修订、例行会议等不因“修订/补充”词命中就无限待审；担保、关联交易等仍核正文实质，不能仅靠标题放行。
无风险关键词不等于完成审核，程序不伪造人工研读记录。复杂语义、内容抽取失败、关键项目不足保持未知。
只有公告身份与内容一致、且独立核对唯一公告数量等于官方总数后才能归一化；冲突、缺页仍失败关闭。
若分页出现重复，先改用互不重叠的日期区间重新核对官方总数；繁忙单日可有界重取，
只有累计唯一 ID 数量达到官方总数且内容无冲突才完成，不能仅删掉重复条目就宣称清单完整。
**有界机器核验不代表核对全部附注、排除隐藏风险或完成专业尽调**。
清单缺失、未覆盖决策时点、最新财报较结构化数据更新、金融业专项指标不足或其他证据冲突时，
状态是“证据不足”，不是通过也不是财务否决；有确认的重大问题才明确否决。
失败只隔离对应个股并在后续运行重试，不拖住其他已核验候选。盘前分别报告通过、排除、证据不足，
不再将“审核没跑完”描述成“市场没有机会”。需研究者裁决的具体内容仍可使用以下严格登记工具。
原文全文审阅仍可以显式登记更强的证据级别，但不能由程序代填审阅人或发现。

银行专项核验要求最新集团口径的资本充足率、不良贷款率、拨备覆盖率及监管合规表述；
保险要求适用主体的核心/综合偿付能力与偿付能力风险评级。不从子公司数据推断集团合格。
这不是增设盈利预测或偏好的收益阈值；缺项、比较期不明或主体不明仍须补证。

自动正文提取采用严格 PDF 解析、逐页检查、限时下载和私有内容缓存；不把扫描页猜成已读全文。
需要 OCR、复杂事项实质判断或历史风险解除核实的个股会列出具体失败原因。
同一问题可以重试，已有完整正文可复用，但不会为了清空“证据不足”栏目而改成通过。

默认读取本机应用数据目录下的 `cache/candidate_evidence`，审阅文件保存在
`candidate_reviews`。以下命令中的代码必须带已核验交易所，如 `601298.SH`；
仅作使用示例，不是对该股票的推荐或已经完成审阅的声明。

## 1. 查看待审阅候选与创建草稿

先运行正常研究流程取得候选的当天取证回执，再执行：

```bash
.venv/bin/python -m ashare_lab.cli.candidate_review status
.venv/bin/python -m ashare_lab.cli.candidate_review template 601298.SH
```

模板仅在回执和完整公告清单有效时创建，输出本机草稿路径。模板的状态为 `pending`，
全部检查项为 `false`，逐条公告分类为 `pending`，不填审阅人、不填结论、不伪造已经阅读的文件。
重复创建同一草稿不会覆盖文件；草稿本身不会成为生产通过证据。

## 2. 下载并研读官方原文

草稿 `available_documents` 列出本轮公告标题、时间、编号和官方链接。
下载其中指定编号：

```bash
.venv/bin/python -m ashare_lab.cli.candidate_review download 601298.SH 公告编号
```

只允许清单中的 `https://static.cninfo.com.cn/finalpage/...PDF`，禁止跳转至其他网站，
每份文件有超时和 50MB 限制。返回相对文件路径、原链接和 SHA256；**下载不等于研读**，
不会自动填写文件角色、发现或通过状态。

研究者应实际阅读最新完整财报、最近年度审计材料及潜在重大风险公告，逐条审阅完整公告清单，
把财务数值与原文核对。编辑草稿时逐项记录：

- 真实审阅人、含时区的完成时间、具体理由；未完成时保持 `pending`。
- `documents`：公告编号、原链接、相对文件路径、SHA256、具体原文发现及角色。
  最新财报角色为 `latest_financial_report`，年度审计为 `annual_audit`，其他风险文档可用 `material_risk`。
- `triage`：每条公告真实判断为 `document_reviewed` 或 `routine_nonmaterial`，并填写理由；
  潜在重大风险公告不能仅凭标题归为常规事项。
- `checklist`：仅实际完成对应工作后逐项确认，包括 `financial_metrics_cross_checked`。
- `status`：证据与研读均完成才可填 `pass`；发现否决事项填 `veto` 并说明。不能批量机械勾选来凑推荐。

报告期不等于首次公告日；最新财报与年度审计角色会核对公告标题和适用期间。
CSMAR 资产负债表不能代替利润、现金流或官方正文。
系统使用决策时最近**已披露**的适用报表：法定披露期限只是最低新鲜度要求，
不是把尚未发布的季度报表当作已知。若官方完整公告清单明确出现更新报告期的财报标题，
而结构化财务数据仍停留在旧报告期，核验保持未知，等源数据更新或人工核对，不能用旧报表放行。
截至 2026-09-29，普通沪深 A 股的最低报告期是 2026 年半年报；只拿到 2026 年一季报不能替代。
结构化行情的 PE(TTM)、PB(MRQ) 只作为带价格截止日的估值背景，不是质量通过证据；
银行、保险等金融机构不套用工业企业负债率、经营现金流阈值，
缺少不良贷款、资本充足率、偿付能力等适用证据时仍保持待核验。

## 3. 验证，再显式登记

```bash
.venv/bin/python -m ashare_lab.cli.candidate_review validate 601298.SH --file /本机草稿绝对路径.json
.venv/bin/python -m ashare_lab.cli.candidate_review register 601298.SH --file /本机草稿绝对路径.json --confirm-reviewed
```

验证不修改正在生效的审阅文件。登记必须显式确认真实研读，且当前清单、财务哈希、文件哈希、
时间与审阅内容全部通过验证；`pending` 或无效草稿不可登记。已有生效文件不会默认覆盖，
确需更新时添加 `--replace-existing`；旧文件和登记审计保存在 `history` 中，可恢复。

回执过期、清单或财务内容变化、缺少原文、文件被修改、未来时间及跨目录路径都会失败关闭。
自动核验方法版本升级到 `candidate-evidence-v2.0.0` 后，旧版当天回执与旧审阅结论也不会被默认为通过；
需要按新回执重新核对并登记。
次日先刷新回执：若出现新公告或财务更正，应重新研读变化，不能沿用旧“通过”。
`status` 会单独提示财务抓取、官方清单抓取或需要的正文审阅哪一步未完成；
抓取失败不构成财务否决。进入人工正文审阅时，应核对最新适用的交易所/巨潮/发行人财报原文及
其后更正，再把 BaoStock 等结构化财务字段与原文交叉核对；机器窄口径检查不能冒充这种全面研读。
退出码：成功操作 `0`，校验结果仍未知 `3`，操作被拒绝或失败 `2`。

可用命令前的 `--cache-dir` 和 `--review-dir` 指定测试目录，默认不需要设置。
本工具不连接券商、不修改持仓、不发送微信、不自动下单；私有回执、原文与审阅记录不提交开源仓库。
