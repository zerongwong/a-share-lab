# 免费收盘链的故障恢复

本机日任务仍为 15:30、18:30、20:00；晚报仍为交易日前夜 21 点窗口。
不购买数据、不连券商、不改只读 CSMAR 基线、不修改交易策略。

## 已实现

- BaoStock 每项请求在独立进程执行，默认 45 秒时限（包括登录、读取和退出）。
  超时子进程被终止，不使用无法取消的后台线程，不改全局 socket 设置。
- 自动收盘同步由 `scheduled_sync_worker` 监管，总时限 12 分钟。
  超时只结束本次独立进程组，释放内核锁；保留此前已验证数据，记录错误并尝试发故障通知。
- 任务运行期间用 `caffeinate -i` 阻止闲置休眠；它不负责唤醒已经休眠或关机的电脑。
- 晚报第一次遇到任务占用就尝试发独立、幂等的未完成提醒，不依赖最后一次重试恰好在 21:45。
  正式计划已受理时不发矛盾提醒；提醒成功不冒充计划成功。
- 晚报确认下一交易日也使用隔离日历连接；不可用时尝试 Tushare 免费日历，
  两者都不可用则报告日期未核定，不凭星期几猜测开市。

## 备用路径及边界

| 数据 | 主源 | 不可用时的备用 |
|---|---|---|
| 交易日历 | BaoStock | 当前 Token 实际可读的 Tushare trade_cal；要求每个自然日覆盖 |
| 上市证券主表 | BaoStock | 当前 Token 实际可读的 stock_basic；包括停牌但仍上市股票 |
| 六个核心指数 | BaoStock | 东财日线，逐一与腾讯核对目标日及前一交易日 |
| 全市场个股日线 | Tushare | 保留有限同源重试；暂无可绕过资格核验的完整备用批次 |
| 个股交叉核验 | AKShare | 保留原核验逻辑，失败时不签发已验证批次 |

这是**元数据与指数的备用增强，不是全市场个股三源任意互换**。
腾讯个股历史前一根收盘不等于除权日的交易所参考昨收，不能为填空而伪造；
个股备用还需完整交易日、证券主表覆盖、交易所昨收和单位合同后才能接入。
Tushare 的元数据若账户无权限，失败并报告；不自动购买积分或宣称账户必有免费权限。

切源只发生在不可用/超时，不在字段、价格或单位质量错误时发生。
东财指数成交量按手转股、成交额为元；腾讯指数成交量按手转股、成交额按万元转元。
两源全部六指数的前后交易日 OHLCV/金额须一致，否则拒绝。该转换只用于指数，禁止复用到个股。
接口没有可依赖的送达保证，局部测试通过也不等于全天或全市场覆盖保证。

新批次单位合同标为 v2，行级 source 保留真正来源，元数据主备选择进入批次回执。
旧 v1 档案不重写；只有整日覆盖、质量及共同截止检查通过后，才追加新的验证记录。

## 运维

安装脚本只管理 `com.zerong.asharelab.daily-sync`。短暂卸载/加载冲突会有限重试，
失败时尝试恢复旧配置，不升级 root 权限。用户不需要手工删锁文件；删文件不能安全解除活锁。
保留 `daily-sync.jsonl` 和 `evening-report.jsonl` 的脱敏退出原因。
既不把“进程启动”当同步完成，也不把“服务商受理”当微信终端已收到。
